## 2. P1 — все три закрыты, проверено на реальных данных

### C-1. Окно ракет

`rocket_accounting(..., peaks=...)` берёт пик из `telemetry.observation_peaks(db, window_sec=60)`,
а не из сделки; сделки без наблюдений падают в `fallback_trades`, источник пишется в
`peak_source`.

Проверил на **реальной телеметрии run6** (распаковал `telemetry.sqlite.gz.part00`):

```
observation_peaks(run6)             → 2 112 минтов
A: сделок, для которых пик найден    → 167 из 167
rocket_accounting(A, peaks)         → rockets 11 / share 6.59 % / p* 5.69 %
rocket_accounting(B, peaks)         → rockets 11 / share 6.67 % / p* 7.35 %
```

Ровно те цифры, что в моём аудите (11 ракет в окне 60 с, p* 5.69 %). До правки было
**3 ракеты и p\* 1.34 %** — то есть в 5 раз оптимистичнее правды. Исправлено верно.

**Оговорка, не блокер:** offset 60 теперь читается только у 1/3 монет (по хешу), поэтому у
остальных 2/3 «пик в окне 60 с» — это фактически пик за 0…15 с. Прогнал симуляцию настоящей
хеш-функции на данных run6: доля ракет получилась **6.0 % вместо 6.6 %** (−9 % относительно).
Мелочь, но в `RUN_NOTES.md` стоит одной строкой: «rocket share измерен на 1/3 выборки,
систематически занижен примерно на 0.6 п.п.».

## 3. Блокер, который остался: лаунчер падает на своём префлайте

```
$ HELIUS_API_KEY=… RUN_DURATION_SEC=60 bash run_rocket2_ab_paper.sh
ERROR: preflight tests failed; no run started.
Ran 192 tests … FAILED (failures=1)
FAIL: test_entry_thresholds_come_from_settings
  assertEqual(profiles['portfolio_b1_narrow'].delta_max_sol, 1.5)
AssertionError: 1.0 != 1.5
```

Причина ровно в порядке строк скрипта: он **сначала** экспортирует `ENTRY_DELTA_MAX_SOL_B1=1.00`,
`ENTRY_BIRTH_MAX_SOL_B2=31.00`, `ENTRY_DELTA_MIN_SOL_B3=0.00`, а **потом** запускает
`python -m unittest discover -s tests`. А `profiles_from_settings()` отдаёт приоритет env
(это правильно для запуска), поэтому тест, который передаёт значения через `settings` и ждёт
`1.5`, видит `1.0`. В чистом окружении тест проходит — я проверил оба варианта.

То есть скрипт сломан не импортом (это починили), а тем, что его собственный префлайт
несовместим с его же окружением. `exit 6` — прогон не начнётся никогда.

**Починить (одна строка в тесте):** тест должен быть независим от окружения —

```python
with patch.dict(os.environ, {}, clear=False):
    for key in ('ENTRY_DELTA_MAX_SOL_B1', 'ENTRY_BIRTH_MAX_SOL_B2', 'ENTRY_DELTA_MIN_SOL_B3', 'ARMS'):
        os.environ.pop(key, None)
    profiles = profiles_from_settings(settings)
```

либо добавить в `profiles_from_settings(settings, env=None)` и передавать `env={}` из теста.

**Почему это всё ещё важно, хотя `START_*` работает:** `START_MAC_LINUX.sh` и
`START_WINDOWS.bat` тесты не запускают и идут сразу в `run_local_session.py` — этот путь жив.
Но `run_rocket2_ab_paper.sh` назван в README «bare entry point with the run #7 preflight»,
лежит в бандле и запускается из `run_overnight_ab_paper.py`. Кто пойдёт по README — получит
`exit 6` и никакого прогона.
