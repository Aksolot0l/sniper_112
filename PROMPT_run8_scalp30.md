# Промпт Кодеру: 30-минутный смоук «один кошелёк, быстрый вход, выход по покрытию комиссий»

Самодостаточный. Запускается **после** того, как принят отчёт по run7 (он уже сдан).
Цель прогона — **не доказать стратегию, а измерить конвейер**: реальную задержку
«детект → решение → филл», реальную стоимость входа и выхода, и сколько сделок успевает
сделать один кошелёк за 30 минут при выходе в первые секунды.

Сразу фиксирую ожидание, чтобы потом не было спора: по данным run7 (3 371 кандидат,
`observations.csv`) выход при покрытии комиссий даёт **−5.4 % на сделку**, выход по времени
на 5-й секунде со стопом −10 % — **+1.0 %**. Поэтому этот прогон читается как «проверка
механики», а не «проверка идеи». Обе цифры пересчитаем на его собственных данных.

---

## 1. Что запускаем

Одна книга, один кошелёк, 30 минут, paper-only, подписей нет.

| параметр | значение | почему |
|---|---|---|
| длительность | 1800 с | смоук конвейера |
| армов | **1** (`portfolio_s`) | по требованию: один кошелёк |
| ставка | 500 ₽ | без изменений |
| банк | 1 500 ₽ | без изменений |
| слотов | 3 | при выходе за 5 с они почти не лимитируют |
| полоса рождения | **30.5–32.0 SOL** | лучшая полоса по данным run7 (+3.46 % средний рост за 5 с) |
| `delta_min` | **0.00** (вход на первом чтении) | чтобы не платить премию ожидания |
| `delta_max` | 2.5 | предохранитель |
| выход | **покрытие комиссий + тайм-аут + жёсткий стоп** | см. §2 |
| лестница Round 6 | **выключена полностью** для этого арма | один эксперимент — одно правило |

## 2. Новый арм и новый режим выхода

### 2.1 Арм `portfolio_s` (single-arm smoke)

Добавить в `ARM_IDS`, `ARM_LABELS`, `ARM_DEFAULTS`, `ARM_ENV_KEYS`:

```python
'portfolio_s': ('ENTRY_BIRTH_MAX_SOL_S', 'v_sol_birth_max')   # 32.0
'portfolio_s': ('ENTRY_DELTA_MIN_SOL_S', 'delta_min_sol')     # 0.0
```

Профиль наследует всё от A, кроме:

```python
v_sol_birth_max = 32.0
delta_min_sol   = 0.0
exit_mode       = 'fee_cover'
fee_cover_pct   = 3.5      # ENV EXIT_FEE_COVER_PCT, измеренная стоимость круга 3.25 %
time_exit_sec   = 5.0      # ENV EXIT_TIME_SEC
hard_stop_pct   = 10.0     # ENV EXIT_HARD_STOP_PCT
```

### 2.2 Режим `fee_cover` в оценке выхода

В том же методе, где сейчас живут SL/TP1/трейл/полка (`portfolio_ab.py`, ~2205–2290),
**до всех остальных правил** поставить:

```python
if profile.exit_mode == 'fee_cover':
    # 1) жёсткий стоп — раньше всего остального
    if pnl_pct <= -profile.hard_stop_pct:
        return f'Hard stop (−{profile.hard_stop_pct:.1f}%)', pos.remaining_tokens_raw
    # 2) покрытие комиссий: продаём ВСЁ, не половину
    if pnl_pct >= profile.fee_cover_pct:
        return f'Fee cover (+{profile.fee_cover_pct:.1f}%)', pos.remaining_tokens_raw
    # 3) тайм-аут
    if held >= profile.time_exit_sec:
        return f'Time exit ({profile.time_exit_sec:.1f}s)', pos.remaining_tokens_raw
    return None, 0
```

Требования:

- **`tp1_sell_pct` не участвует**: продаём весь остаток, никаких половин.
- Проверка выхода — **на каждом тике**, не только на штатных отметках 5/15/60 с.
- Если цена недоступна — позиция не закрывается (fail-closed), но пишется `unpriced_tick`.
- `exit_reason_kind()` должен узнавать три новых причины (`fee_cover`, `time_exit`, `hard_stop`),
  иначе они свалятся в `unknown`.

### 2.3 Разрешить прогон без арма A

Сейчас `profiles_from_settings()` бросает `ValueError('ARMS must contain portfolio_a')`.
Добавить:

```python
if os.getenv('ALLOW_SINGLE_ARM', '').strip() in {'1','true','yes'}:
    pass          # единственный арм допустим, сравнение не строится
```

В манифест писать `reference_arm: null`, `mode: 'single_arm_smoke'`, и в отчёте —
строку «сравнения армов в этом прогоне нет».

## 3. Инструментация — то, ради чего прогон и делается

1. **Цепочка задержки на каждую сделку** (в `closed_trades` и в `decisions.csv`):

   | поле | что значит |
   |---|---|
   | `t_detect_ms` | от пакета WSS (создание) до записи кандидата |
   | `t_filters_ms` | от кандидата до окончания security-проверок |
   | `t_read_ms` | от окончания фильтров до чтения кривой, по которому считалась цена |
   | `t_fill_ms` | от чтения до записи филла |
   | `t_total_ms` | сумма от создания до филла — **это и есть фактическая «0.2 с»** |

   Ожидание 200 мс, скорее всего, не выполнится: в run7 медиана `entry_lag_ms` была 96–150 мс
   только на модель, а security-проверки идут через RPC. Пусть будет измерено, а не обещано.

2. **Три цены на каждую закрытую сделку**: `price_at_3s`, `price_at_5s`, `price_at_10s`
   относительно цены входа. Нужны, чтобы после прогона посчитать альтернативные выходы
   на его же данных без второго запуска.

3. **Реальная стоимость круга**: по сделкам, где цена на выходе равна цене входа
   (в пределах 0.01 %), писать `round_trip_cost_pct` — это проверка нашей цифры 3.25 %.

4. **Счётчик «не успели»**: сколько кандидатов в полосе отброшено из-за отсутствия цены,
   занятых слотов и таймаутов чтения.

## 4. Что прислать

- zip-бандл, `BUILD`-хеш, вывод тестов (192+ зелёных, включая новые на `fee_cover`).
- `SUMMARY.md` со таблицами:
  1. `n`, `sum`, `mean`, `median`, `sd` по одной книге; `exit_breakdown` по трём новым причинам;
  2. распределение `t_total_ms` (медиана, p90, max) и сколько сделок реально уложились в 200 мс;
  3. `entry_fill_premium_pct` и `round_trip_cost_pct` (медиана) — против наших 1.41 % и 3.25 %;
  4. пересчёт двух альтернативных выходов на этих же сделках: «держать до 5 с» и «держать до 10 с»;
  5. фаннел: сколько кандидатов в полосе 30.5–32, сколько вошло, сколько отброшено и почему.
- Явная строка: `early_stop_reason`, `paper_only: true`, `signed_transactions: 0`.

## 5. Приёмка

| проверка | порог |
|---|---|
| `paper_only` | true, подписей 0 |
| длительность | ≥ 1 790 с |
| `early_stop_reason` | null |
| невосстановленные ошибки RPC | ≤ 2 % |
| rps среднее / в любом 10-мин окне | ≤ 1.8 / ≤ 2.2 |
| `dropped_events`, `write_errors` | 0 / 0 |
| позиции на конце | 0 открытых (иначе закрыть принудительно и записать) |
| `fee_cover` срабатывает | ≥ 1 раз (иначе правило не проверено) |

## 6. Чего в этом прогоне нет

- **Нет сравнения армов** — одна книга, эталона A нет. Все выводы «лучше/хуже» делать нельзя,
  только абсолютные числа и распределения.
- **Нет `no_progress`, полки, трейла, TP1** — они выключены, а не настроены.
- **30 минут не дают статистики**: ожидается ~30 сделок при потоке 60/ч в полосе.
  Всё, что мы получим про деньги, — это −5.4 % против +1.0 % из прошлого расчёта,
  проверенные на 30 сделках, то есть «знак не проверен». Прогон нужен для конвейера
  и стоимости исполнения.
