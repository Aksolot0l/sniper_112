# Проверка кода под run 9 (промпт v5): что есть, чего нет, где порвётся

Проверял ветку Кодера `arena/062dc210-sniper-112`. **HEAD = `52d6e53`, это сборка run8** (последний
коммит 23.10 15:49, PR #1 открыт, но там только логи run8). Кода под run 9 в ветке нет вообще.
Ниже — что из плана уже поддерживается, что придётся дописать и какие ловушки испортят результат,
даже если прогон стартует.

---

## 1. Что уже работает и менять не надо

| требование v5 | состояние |
|---|---|
| выход `fee_cover` (стоп −10 % → тейк 3.5 % → часы 5 с) | есть целиком, `portfolio_ab.py:2518` |
| `MARK_POLL_SEC` | есть, env, по умолчанию **0.15** (`portfolio_ab.py:710`) |
| offsets только `[0, 5]` | есть, env `TELEMETRY_OBSERVATION_OFFSETS_SEC`, **по умолчанию уже `0,5`** (`main_ab.py:62`) |
| `ENTRY_LATENCY_MS=0` | есть |
| `ALLOW_SINGLE_ARM=1` | есть |
| фильтр входа по книгам | уже пер-книжный: `ABProfile.entry_check` (`portfolio_ab.py:167`), вызов из `_consider_entry` (`:1565`) |

Вывод: полоса рождения — **уже поле профиля**, а не глобальная настройка. Разные полосы по книгам
требуют не переписывания логики, а одной записи в `ARM_DEFAULTS`.

## 2. Что не даст прогону даже стартовать

`ARMS=portfolio_s0,portfolio_s2` → `profiles_from_settings` бросит
`ValueError: unknown ARMS entry: portfolio_s2` (`portfolio_ab.py:224-231` — `ARM_IDS`).
Книги S2 в коде нет.

## 3. Что придётся дописать

### 3.1 Книга S2 (полоса как граница книги) — 10 строк

```python
ARM_IDS += ('portfolio_s2',)                       # :224
ARM_LABELS['portfolio_s2'] = 'S2'                  # :249
ARM_DEFAULTS['portfolio_s2'] = {'v_sol_birth_min': 31.96,
                                'delta_min_sol': 0.0, 'delta_max_sol': 1.00}
ARM_ENV_KEYS['portfolio_s2'] = ('ENTRY_BIRTH_MIN_S2', 'v_sol_birth_min')   # :260
```

Логику не трогать: `entry_check` уже читает `profile.v_sol_birth_min`.

### 3.2 Фильтр копий имени — единственное реально новое правило

Сейчас в коде **нет ни одного упоминания** `copies` (проверено grep’ом по всему дереву).

Требования, без которых эффект исчезнет:

1. **Считать по всем замеченным монетам**, а не по прошедшим фильтры сигналам. В моём реплее
   (8 ч, 3 371 монета) копии считались по всей популяции; если считать только по `_signal`
   (в run8 это 373 записи на книгу вместо 628 кандидатов), счётчик занизится и фильтр почти
   ничего не отсечёт.
2. Ключ — `symbol.lower().strip()`. Пустой символ **не** фильтровать.
3. Окно — 120 с строго назад от момента текущего кандидата (список времён, старое вычищать).
4. Решение — пер-книжное: `profile.max_name_copies_120s` (`None` = выключено у S0, `0` у S2).
   Счётчик писать в `closed_trades` (`name_copies_120s`) и в причину отказа `name_copies_120s`.
5. RPC не нужен, состояние в памяти.

### 3.3 «Призрак» после выхода + `price_at_5s` + `delta_at_entry_sol`

Сейчас нет ни `post_exit`, ни `price_at_5s`, ни `delta_at_entry_sol`.

Хорошая новость: в цикле меток уже есть батч `getMultipleAccounts` по всем кривым
(`portfolio_ab.py:2086-2092`, `curve_addresses = list(dict.fromkeys(...))`), и при отсутствии
открытых позиций цикл вообще не делает RPC (`:2068`). Значит «призрака» можно добавить в тот же
батч и получить **0 дополнительных запросов**: держать `ghost: mint -> (curve, exit_epoch, entry_price)`
10 с и включать их кривые в `curve_addresses`.

Писать `post_exit.csv`: `portfolio, mint, exit_at_epoch, sec_since_exit, price_usd,
pnl_vs_entry_pct, pnl_vs_exit_pct`, точки +0.5/+1/+2/+5/+10 с.
`price_at_5s` брать из того же механизма, даже если позиция закрылась раньше.

### 3.4 Манифест и отчёт врут про книги

`_strategy_metadata()` (`main_ab.py:901`) — жёсткий словарь с A/B1/B2/B3/S1/S0, и `profiles`
(`:1075-1081`) тоже. S2 не появится в манифесте → моя приёмка («полосы по книгам») провалится,
хотя прогон будет правильный. Надо добавить S2 в оба места.

Там же `_safe_manifest().common` (`:1089-1091`) жёстко пишет `initial_balance_rub: 1500`,
`position_size_rub: 500`, `max_slots: 3` — для run 10 (S2b: 1 000/3 000) это будет прямая ложь
в манифесте. Для run 9 не критично, для run 10 обязательно.

### 3.5 Приёмка заточена под 30-минутный run8

`main_ab.py:461-500`: порог `длительность ≥ 1 790 c` и проверка `fee_cover сработал ≥ 1 раза
в каждой книге`. Для 12-часового прогона первое даст «красный» отчёт, второе бессмысленно
(тейк может не сработать). Пометить как информационные, а не блокирующие.

## 4. Ловушки, которые испортят результат, даже если всё запустится

1. **Общая переменная полосы.** `ENTRY_BIRTH_MIN_SOL` читается в `shared` (`portfolio_ab.py:341`).
   Если Кодер выставит `31.96` в общем env «для S2», S0 получит ту же полосу и **перестанет быть
   контролем** — сравнение мёртвое, а по отчёту это не будет видно. Проверять только по манифесту:
   S0 `30.50–34.50`, S2 `31.96–34.50`.
2. **Каденс.** Лончер `run_local_session.py:102` по умолчанию ставит `MARK_POLL_SEC=0.15`.
   В v5 требуется 0.25 — задавать явно, иначе получим повтор run8 с адаптацией на ходу.
3. **ARMS.** Лончер по умолчанию `portfolio_s1,portfolio_s0` (`:89`). Задавать явно.
4. **Фильтр копий на весь прогон вместо книги** — тогда S0 тоже потеряет копии и станет не S0.
5. **`auto_top_up`** пополняет книгу до `initial_balance_rub`. Для run 9 это нормально, но число
   пополнений надо отчитывать по каждой книге, иначе ₽-итог будет читаться как доходность.

## 5. Что я проверю в смоуке, когда он появится

1. Манифест: полосы S0 `30.50–34.50` / S2 `31.96–34.50`, копии `off` / `0`, каденс `0.25`.
2. `name_copies_120s` есть в каждой сделке и **у S0 он не всегда 0** (иначе фильтр считается
   по сигналам, а не по популяции — и это видно сразу).
3. `exports/post_exit.csv` непуст, ≥ 5 меток на каждый выход, интервалы как заявлено.
4. `delta_at_entry_sol` и `price_at_5s` заполнены; `price_at_5s` есть даже у сделок, закрытых
   по тейку на 1-й секунде.

## 6. Оценка объёма

Пункты 3.1, 3.4, 3.5 — по несколько строк каждый. 3.2 — новый маленький модуль (реестр символов)
плюс поле профиля. 3.3 — расширение цикла меток и экспорт CSV. Ничего из этого не меняет
существующую логику входа и выхода, поэтому риск сломать run8-поведение низкий, если не трогать
`_exit_trigger`, `_apply_sell_fill` и `_consider_entry` (кроме вставки проверки копий).
